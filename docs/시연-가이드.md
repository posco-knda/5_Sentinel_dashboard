# Sentinel 시연 영상 가이드 (5분)

촬영 전에 이 문서만 보면 됩니다. 1) 사전 준비 → 2) 차별점 한눈에 → 3) 큐시트 → 4) 예상 질문 → 5) 문제가 생겼을 때 순서입니다.

핵심 메시지 한 줄: **"예측 정확도가 아니라 정비 결정을 바꿨습니다 — 사후 정비보다 30%, 가장 잘 맞춘 정기 정비보다도 22% 아낍니다."**

## 1. 사전 준비

### 1-1. 배포 확인 (촬영 전날)
1. `feat/maintenance-calendar` → `main` PR을 병합한다. (Vercel이 1~2분 안에 재배포)
2. 터미널에서 점검한다.
   ```bash
   npm run demo:check
   ```
   모두 ✓가 나오면 파일·Slack·AI 연동이 살아 있는 것이다. ✗가 있으면 그 줄의 안내대로 고친다.
3. 운영 주소에서 로그인 → 현황 맨 위에 **세계 지도 위를 날아다니는 비행기**가 보이면 최신 버전이다.

### 1-2. 촬영 환경
| 항목 | 설정 |
|---|---|
| 브라우저 | Chrome 한 개, **프로필 하나에 창(또는 탭) 두 개** — 메신저가 같은 브라우저 안에서 동기화되기 때문 |
| 화면 | 창 크기 1600×900 안팎, 확대 100%, 북마크 줄·확장 프로그램 아이콘 숨김, 라이트 테마 |
| 소리·알림 | 운영체제 알림 끄기(방해 금지), 메신저·메일 종료 |
| 해상도 | 녹화 1920×1080, 30fps 이상 (OBS 또는 윈도우 게임 바 `Win+G`) |
| 마우스 표시 | 주소 뒤에 `present=1` 을 붙이면 큰 원과 클릭 물결이 나온다 (아래 주소 참고) |
| 모바일 | **폰 크기 창**(`420×860`)을 PC 창 옆에 둔다 — 아래 1-4 |
| Slack | 정비 알림 채널과 결재 알림 채널을 미리 열어 두고, 알림 도착 장면은 **창을 따로 녹화**해서 편집으로 붙인다 |

### 1-3. 시작 주소 (화면에는 글자가 남지 않는다)
| 용도 | 주소 |
|---|---|
| 처음 상태로 초기화하고 로그인 화면부터 시작 | `https://5-sentinel-dashboard.vercel.app/?demo=reset&present=1` |
| 담당자로 바로 시작 | `…/?as=planner&present=1` |
| 책임자로 바로 시작 (초기화 없이) | `…/?as=manager&present=1` |
| 마우스 표시 끄기 | `…/?present=0` |

> `demo=reset` 은 이 브라우저에 저장된 처리 이력·메신저·할 일·설정을 모두 지우고 처음 상태(검토 중 18대 · 결재 대기 10대 · 정비 예정 12대 · 반려 3대 · 완료 6대)로 되돌린다. **촬영 직전에 한 번만** 하고, 두 번째 창에는 쓰지 않는다.

### 1-4. 두 창 배치 (PC + 폰 크기 창)
실제 담당자는 폰으로 많이 보므로, **한 화면에 PC 창과 폰 크기 창을 나란히** 두고 두 사람이 동시에 일하는 것처럼 보여 준다. 담당자는 PC, 책임자는 폰으로 결재하는 설정이다.

1. 브라우저 창 하나(PC 창)를 약 `1380×860` 크기로 맞추고 `…/?demo=reset&present=1` 로 연다. (로그인 화면부터 시작)
2. 그 창에서 `F12` → 콘솔에 아래를 붙여넣어 **폰 크기 창**을 연다. (팝업 차단은 허용)
   ```js
   window.open(location.origin + '/?as=manager&present=1', 'phone', 'width=420,height=860,left=1480,top=40')
   ```
3. 두 창을 화면 왼쪽(PC)·오른쪽(폰)에 놓고 녹화한다. 폰 창은 이미 **책임자로 로그인**되어 있고, PC 창은 로그인 화면이므로 담당자로 로그인하면서 시작한다.
4. 마지막 폰 장면(4:40~)은 편집에서 폰 창을 **확대**하거나 OBS에서 창 캡처를 따로 잡아 쓴다. 폰 모양 테두리는 편집에서 씌우면 된다(선택).

> **실제 폰은 쓰지 않는다.** 이 시스템은 처리 이력·메신저를 *브라우저 저장소*에 두기 때문에, 다른 기기의 폰과는 실시간으로 이어지지 않는다. 같은 브라우저의 좁은 창은 화면 구성이 폰과 같고(폭 768px 미만에서 모바일 화면), 두 창이 즉시 동기화된다. 실제 폰 장면이 꼭 필요하면 **독립 컷**으로 따로 찍는다.

### 1-5. 리허설 순서
`demo=reset` → 1번 창에서 담당자로 시나리오 전체 한 번 → 다시 `demo=reset` → 본 촬영.
(리허설에서 #31을 이미 승인해 버리면 본 촬영에서 같은 장면을 못 찍기 때문)

### 촬영 요령
- 동작 사이에 **1초 멈춤**을 둔다. 편집에서 배속을 올리기 쉽다.
- 호버 카드가 떠 있으면 비행기가 멈추므로, 읽을 시간을 준다.
- 로딩 비행기와 3D는 처음 열 때만 잠깐 불러온다. **리허설에서 한 번 열어 두면** 본 촬영에서는 즉시 뜬다.
- 챗봇은 첫 응답이 1~3초 걸린다. 입력 뒤 기다리는 동안 멘트를 이어 간다.
- 5분을 넘기면 **몽타주(4:20–4:40)와 폰 컷**부터 줄이고, 정비 방식 비교(3:25)는 줄이지 않는다.

## 4. 예상 질문과 답변

| 질문 | 답 |
|---|---|
| 데이터가 뭔가요? | NASA C-MAPSS **FD004**(운전조건 6종·고장모드 2종)의 공식 시험 엔진 248대입니다. 공개 시뮬레이션 데이터라 실제 항공사 데이터는 아닙니다. |
| 모델 정확도는? | GRU로 남은 수명을 예측하고, 시험 248대 기준 평균 오차 약 17 cycle, RMSE 약 25 cycle입니다. 이 오차로 불확실성 구간과 고장 확률을 계산합니다. |
| −30%는 실제 효과인가요? | 아닙니다. 시험 데이터의 **실제 남은 수명을 사후에 알고** 비교한 시뮬레이션입니다. 경보 구간에 들어온 115대 기준이고, 비용은 공개 자료 기반 **가정값**입니다. 정기 정비는 이 데이터에서 가장 유리한 주기를 골라 일부러 유리하게 비교했습니다. |
| 최적 주기·여유는 일반화되나요? | 같은 데이터에서 고른 값이라 그대로 일반화하면 안 됩니다. 별도 엔진으로 검증하는 것이 다음 단계입니다. |
| 왜 정기 정비가 지는가요? | 엔진마다 수명이 126~525 cycle(분석 대상 115대 기준)로 크게 달라서, 한 주기로는 짧게 사는 엔진은 고장 나고 길게 사는 엔진은 아깝게 교체하기 때문입니다. |
| 챗봇은 환각이 없나요? | 모델이 숫자를 직접 말하지 않고 **시스템 도구를 호출한 결과만** 설명하게 했고, 읽기 전용이며 근거 보기를 제공합니다. 서버는 허용된 도구 이름만 받습니다. |
| 사람이 개입하나요? | 담당자 검토 → 책임자 승인 두 단계이고, 한계일을 넘기는 일정은 사유가 필수인 **긴급 예외 승인**으로 분리됩니다. 모든 판단자와 사유가 이력에 남습니다. |
| 서버에 저장하나요? | 시연 환경이라 브라우저에 저장합니다. 실제 서비스에서는 서버 저장·권한·감사 로그가 필요합니다. |
| 운항 현황 지도는 실시간인가요? | 아닙니다. 노선과 위치는 표시용이고, **비행기 색 비율과 호버 카드의 수치는 실제 엔진 데이터**입니다. |

## 5. 문제가 생겼을 때

| 증상 | 원인과 대처 |
|---|---|
| 화면이 이전 버전이다 | PR 병합 전이다. 병합 후 Vercel 배포가 끝날 때까지 기다린 뒤 강력 새로고침(`Ctrl+Shift+R`) |
| 메신저가 상대 창에 안 보인다 | 두 창이 같은 브라우저·같은 프로필인지 확인. 시크릿 창과 일반 창은 저장소가 분리되어 동기화되지 않는다 |
| 챗봇이 "답변을 만들지 못했습니다" | 무료 한도 초과 가능성. 30초 뒤 재시도, 안 되면 챗봇 장면은 미리 녹화한 컷으로 대체 |
| Slack 알림이 안 온다 | `npm run demo:check`로 `/api/status` 확인. 설정 화면의 "연동"에서도 상태를 볼 수 있다 |
| 3D 모델이 안 뜬다 | 그래픽 가속이 꺼진 브라우저일 수 있다. 자동으로 2D 구조도로 대체되며, Chrome 설정에서 "하드웨어 가속 사용"을 켠다 |
| 리허설로 데이터가 어질러졌다 | `…/?demo=reset&present=1` 로 다시 접속 |
| 처음부터 다시 보고 싶다 | 같은 주소로 `demo=reset` — 로그아웃되고 로그인 화면에서 시작 |
